# MusicTrainer

Приложение для тренировки музыкального слуха. Пользователь слышит интервал и подбирает
его на слух, ведя пальцем по осциллографу — тот работает как «невидимый джойстик»:
по горизонтали меняется частота, по вертикали громкость. Отклонение подобранной
ноты в центах записывается в статистику.

Звук не берётся из файлов, а **генерируется процедурно**: numpy считает волновую
форму, pygame выводит её в звуковую карту. Поэтому частота меняется непрерывно,
без щелчков и подгрузок.

| | |
|---|---|
| Интерфейс | Kivy (7 экранов) |
| Звук | pygame.mixer + numpy, 44100 Гц, моно |
| Режимы | мелодический, гармонический |
| Интервалов | 22, диапазон тоники C3–C5 |
| Тембров | 5 (синус, орган, скрипка, флейта, кларнет) |
| Хранение данных | JSON в рабочей директории |

```
MusicTrainer/
├── src/                  Код приложения
│   ├── main.py           Точка входа
│   ├── core/             Звуковой движок, микшер, тембры, статистика
│   ├── exercises/        Логика упражнений, настройки, экраны упражнений
│   ├── screens/          Меню, джойстик, статистика, отладка
│   └── ui/               Базовые виджеты и элементы управления
├── docs/                 Документация

├── run.bat               Запуск на ПК
├── build_android.bat     Сборка APK локально через Docker
├── get_apk.bat           Скачать APK, собранный в GitHub Actions
```

Файлы `exercise_settings.json`, `exercise_progress.json`, `data/` и `sessions/`
создаются приложением при работе и хранят пользовательские данные. В репозиторий
они не попадают.

# Часть 1. Запуск на ПК (Windows)

## Рабочие версии

Комбинация ниже проверена — приложение на ней запускается и работает:

| Компонент | Версия | Примечание |
|-----------|--------|------------|
| Python | **3.13.2** | подойдёт любой 3.11+ |
| Kivy | **2.3.1** | закреплено в `requirements.txt` |
| pygame | **2.6.1** | закреплено в `requirements.txt` |
| numpy | **2.5.2** | версия не закреплена, берётся свежая |

## Установка

Один раз создать окружение и поставить зависимости:

```
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
```

## Запуск

```
run.bat
```

Можно двойным кликом из проводника. Скрипт сам переходит в корень проекта
и включает UTF-8 режим.

Вручную то же самое:

```
set PYTHONUTF8=1
.venv\Scripts\python src\main.py
```

**Два обязательных условия:**

Запускать **из корня проекта** — приложение сохраняет настройки и статистику
относительно текущей рабочей директории, а не относительно `main.py`.

`PYTHONUTF8=1` обязателен — код печатает emoji в консоль, а Windows-консоль
в кодировке cp1251 падает на них с `UnicodeEncodeError` ещё до старта окна.

## Если что-то не работает

Проверить, что все модули импортируются:

```
.venv\Scripts\python tools\check_imports.py
```

Скрипт по очереди грузит каждый модуль приложения и показывает, какой именно
не поднимается. Внутри самого приложения есть экран **DIAGNOSTICS** —
самопроверка звука, виджетов и экранов (16 тестов).

# Часть 2. Сборка и установка на Android

Buildozer не работает на Windows напрямую, поэтому APK собирается в Linux —
либо в контейнере Docker у вас, либо на сервере GitHub. Второй способ быстрее
и не занимает вашу машину.

## Рабочие версии

Эта комбинация проверена: APK собирается и приложение запускается на телефоне.

| Компонент | Версия | Откуда берётся |
|-----------|--------|----------------|
| Python на машине сборки | **3.12** | `Dockerfile` |
| buildozer | **1.6.0** | `Dockerfile` |
| python-for-android | **master** | клонируется buildozer'ом |
| Python в приложении | **3.13.9** | пин в `buildozer.spec` |
| Kivy | **2.3.1** | рецепт p4a — как на ПК |
| pygame | **2.6.1** | пин в `buildozer.spec` — как на ПК |
| numpy | **2.3.0** | рецепт p4a |
| Android NDK | **r28c** | `buildozer.spec` |

⚠️ **Версии Python и pygame менять нельзя без крайней нужды.** Они зажаты
с двух сторон: numpy требует Python не ниже 3.11, загрузчик p4a не стартует
ниже 3.13, а pygame не собирается выше 3.13. Рабочее окно — ровно 3.13.
Подробный разбор всех отказов — в [docs/ANDROID.md](docs/ANDROID.md).

## Совместимость устройств

| Параметр | Значение |
|----------|----------|
| Архитектура | `arm64-v8a` — все телефоны с 2016 года |
| Минимальная версия | Android 8.0 (API 26) |
| Целевой API | 31 |

## Способ 1: собрать в GitHub Actions (рекомендуется)

Сборка запускается автоматически при push в ветки `main` и `Vizelb_dev`,
занимает около 16 минут. Запустить вручную, без коммита:

```
gh workflow run "Build Android APK" --ref Vizelb_dev
```

Готовый APK **не появляется на диске сам** — он остаётся в хранилище артефактов
GitHub на 90 дней. Забрать и сразу поставить на телефон:

```
get_apk.bat install
```

Скрипт найдёт последнюю успешную сборку, скачает APK в `bin/` и установит его
на подключённый телефон. Без аргумента — только скачает.

Нужен GitHub CLI, авторизованный один раз командой `gh auth login`.

## Способ 2: собрать локально

```
build_android.bat
```

Нужен установленный и запущенный Docker Desktop. Первая сборка занимает
40–90 минут и качает Android SDK/NDK (~3 ГБ), последующие быстрее за счёт кэша.
`build_android.bat clean` стирает кэш.

На медленном канале этот способ непрактичен — загрузка нескольких гигабайт
может растянуться на часы.

## Установка на телефон

### Через USB

На телефоне включить отладку:

1. Настройки → **О телефоне** → нажать **«Номер сборки»** семь раз
2. Настройки → **Для разработчиков** → включить **«Отладка по USB»**
3. Подключить кабелем, на телефоне разрешить отладку

Кабель должен быть для передачи данных, а не только для зарядки; в шторке
уведомлений выбрать режим «Передача файлов».

Дальше `get_apk.bat install` поставит APK сам. Или вручную:

```
adb install -r bin\musictrainer-17.5-arm64-v8a-debug.apk
```

### Без кабеля

Скопировать APK из `bin/` на телефон любым способом и открыть файловым
менеджером. Android попросит разрешить установку из неизвестных источников —
это нормально для отладочной сборки.

## Если приложение падает на телефоне

Python-приложение под Android при аварии не показывает ошибку на экране —
процесс просто закрывается. Traceback уходит в системный журнал:

```
adb logcat -s python
```

p4a направляет весь вывод Python в тег `python`, поэтому там будут ровно те же
сообщения, что видны в консоли на ПК.

## Замечания

**Публикация в Google Play.** Текущая сборка отладочная и подписана debug-ключом.
Для публикации нужен `android.api` не ниже 34 и подпись релизным ключом.

**Графические подмодули pygame на Android не работают** — они требуют инструкций
SSE2, которых нет на ARM. Приложению это не мешает: графику рисует Kivy,
от pygame нужен только `pygame.mixer`. Но рисовать средствами pygame не выйдет.
